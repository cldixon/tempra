Editing a concept

How a person edits a concept in the app, and how a save meets a write that landed meanwhile.

Human-reviewed · Design · seq 212 · claude-code/laptop, 2 h ago

The reader, made editable

Edit does not open a different page. The same reader that drew the concept turns editable in place, so the person's eye never leaves the paragraph they were reading. Wordgard's compartment flips a facet; the document, its decorations and the comment anchors stay where they are.

The frontmatter sits above the body as a plain form. Fields the service stamps (verified, generated) are shown but never sent back.1

Saving with a note

Save needs a one-line note, the same note an agent writes in X-Note. The ledger records a human edit exactly as it records an agent's: who, when, the note, the files touched.The ledger records a human edit exactly as it records an agent's: who, when, the note, the files touched. There is no separate human history.

The request carries If-Match with the hash the edit started from. Most saves succeed. The interesting case is the one that does not.

When someone wrote meanwhile

A 412 means the concept moved under the edit. The app fetches the version there now and merges three ways: the base, the person's text, and theirs. Changes on different lines combine without a word. Overlapping changes are shown side by side, and the person picks.2

The edit keeps its base. Saving again after a second write meets the 412 again and merges again; nothing written meanwhile is ever overwritten.

While an edit is open, the page is frozen on the version it started from. A write by someone else shows the banner and waits; it is merged at save, never swapped in under the person's hands. See Live feed for how the banner arrives.

Leaving

Leaving with unsaved edits asks first, in the app's router and in the tab itself. Cancel drops the edit after the same question. Escape does nothing: it is too easy to press.
